# Mengganti model embedding ke multilingual-e5

Panduan memindahkan embedding dari model API (default:
`text-embedding-3-*` lewat `BASE_URL`) ke **multilingual-e5** yang berjalan
lokal di server lewat sentence-transformers.

Tidak ada kode yang perlu diubah. Dukungan e5 sudah ada di
`app/rag/local_embeddings.py`; yang berubah hanya `.env`, dependensi, dan isi
kolom `chunks.embedding`.

## Ringkasan

```bash
cd api
uv sync --extra local                                  # 1. dependensi
# 2. ubah .env: EMBED_PROVIDER=local, EMBED_MODEL=intfloat/multilingual-e5-small
python -m scripts.reindex_embeddings --dry-run         # 3a. uji model
python -m scripts.reindex_embeddings                   # 3b. hitung ulang embedding
# 4. restart API
python -m eval.calibrate_threshold --dataset eval/data/eval_set.jsonl \
  --negatives eval/data/negatives.txt                  # 5. kalibrasi ambang
python -m eval.run_eval --dataset eval/data/eval_set.jsonl --k 5   # 6. evaluasi
```

Langkah 3 dan 5 **tidak boleh dilewati**. Keduanya gagal tanpa pesan galat:
chatbot tetap menjawab, hanya saja jawabannya diambil dari dokumen yang salah
atau tidak pernah menolak lagi.

## Lokal atau lewat gateway

e5 dapat dijalankan dengan dua cara. Langkah 3–6 di bawah sama untuk keduanya.

| | `EMBED_PROVIDER=local` | `EMBED_PROVIDER=api` |
|---|---|---|
| Tempat model berjalan | proses API, lewat sentence-transformers | endpoint `BASE_URL` (gateway) |
| Dependensi | `uv sync --extra local` (torch) | tidak ada tambahan |
| `EMBED_MODEL` | nama Hugging Face, mis. `intfloat/multilingual-e5-small` | nama model **menurut gateway**; harus mengandung `e5` |
| Biaya | $0 | dari `usage.cost` gateway, bila dilaporkan |

Dengan `EMBED_PROVIDER=api`, model yang namanya mengandung `e5` dibangun sebagai
`E5ApiEmbeddings` (`app/rag/providers.py`): awalan `query: `/`passage: ` dan
padding ke 1024 dimensi dipasang di sisi API, dan parameter `dimensions` tidak
dikirim (e5 tidak mengenalnya). Gateway cukup meneruskan teks apa adanya.

Per 2026-09-25, gateway proyek ini **belum** melayani `multilingual-e5-small`:
OpenRouter tidak memilikinya, dan `openrouter/intfloat/multilingual-e5-large`
membalas 502 timeout. `.env` sudah menunjuk ke `intfloat/multilingual-e5-small`;
sesuaikan `EMBED_MODEL` dengan nama yang dipakai gateway begitu model tersedia,
lalu jalankan langkah 3. Sampai saat itu, pertanyaan mahasiswa gagal di langkah
pencarian dokumen.

Uji endpoint gateway sebelum re-index:

```bash
python -m scripts.reindex_embeddings --dry-run   # memanggil model sekali, memeriksa dimensi
```

## Memilih varian

| Model | Dimensi | Kapan dipakai |
|---|---|---|
| `intfloat/multilingual-e5-small` | 384 | Default yang dirancang di `flow.md`. Ringan, cukup untuk CPU. |
| `intfloat/multilingual-e5-base` | 768 | Lebih akurat, kira-kira 2–3× lebih lambat. |
| `intfloat/multilingual-e5-large` | 1024 | Paling akurat. Berat untuk CPU; pertimbangkan hanya bila server punya GPU. |

Semua varian muat di kolom `chunks.embedding` (1024 dimensi). Model yang
menghasilkan lebih dari 1024 dimensi ditolak saat meng-embed; `reindex_embeddings
--dry-run` memeriksanya lebih dulu.

Mulai dari `e5-small`. Naik ke varian lebih besar hanya bila langkah 6
menunjukkan Recall@5 belum mencapai target, dan bandingkan durasi "Pencarian
dokumen" di halaman Log dashboard sebelum dan sesudahnya.

## Langkah demi langkah

### 1. Pasang dependensi lokal

```bash
cd api
uv sync --extra local
```

Ekstra `local` (lihat `pyproject.toml`) memasang `sentence-transformers` beserta
torch, ratusan MB. Tidak ikut terpasang secara bawaan karena tidak dibutuhkan
selama `EMBED_PROVIDER=api`.

Periksa:

```bash
python -c "import sentence_transformers; print(sentence_transformers.__version__)"
```

### 2. Ubah `.env`

```env
EMBED_PROVIDER=local
EMBED_MODEL=intfloat/multilingual-e5-small
```

- `EMBED_PROVIDER=local` memuat `EMBED_MODEL` lewat sentence-transformers di
  proses API, bukan lewat `BASE_URL`.
- `EMBED_MODEL` adalah nama model di Hugging Face. Model diunduh sekali saat
  pertama dipakai dan disimpan di cache Hugging Face (`~/.cache/huggingface`,
  atau `HF_HOME` bila diisi).

`EMBED_MODEL` sengaja **tidak** dapat diubah dari halaman Konfigurasi: mengganti
model menuntut re-index, jadi ia bukan setelan yang boleh berubah sambil
layanan berjalan.

### 3. Hitung ulang embedding seluruh chunk

```bash
python -m scripts.reindex_embeddings --dry-run
python -m scripts.reindex_embeddings
```

**Wajib.** Vektor dari dua model berbeda tidak dapat dibandingkan. Pertanyaan
yang di-embed e5 terhadap chunk yang masih di-embed model lama menghasilkan
skor acak, dan tidak ada galat yang memberi tahu.

- `--dry-run` memuat model, memastikan dimensinya cocok dengan kolom, dan
  menghitung jumlah chunk tanpa mengubah apa pun. Jalankan ini dulu: sekaligus
  mengunduh model.
- Tanpa `--dry-run`, seluruh chunk di-embed ulang dalam **satu transaksi**.
  Gagal di tengah jalan berarti tidak ada yang berubah, bukan indeks yang
  separuh model lama separuh model baru.
- Hanya kolom `embedding` yang diperbarui. Teks chunk, index fulltext (`tsv`),
  dan pemecahan dokumen tidak disentuh, jadi PDF tidak perlu diunggah ulang.
- `--batch-size N` mengatur jumlah chunk per panggilan model. Turunkan bila
  memori server terbatas.

Selama re-index berjalan, pertanyaan mahasiswa yang masuk masih dicocokkan
dengan vektor lama. Jalankan di luar jam ramai, atau nyalakan kill switch dulu.

### 4. Restart API

```bash
pm2 restart api        # produksi
# atau hentikan lalu jalankan ulang uvicorn saat pengembangan
```

`uvicorn --reload` hanya memuat ulang saat berkas `.py` berubah, **bukan** saat
`.env` berubah. Tanpa restart, API masih memakai model lama untuk pertanyaan
sementara chunk sudah berisi vektor e5.

Model dimuat sekali per proses saat embedding pertama diminta, jadi pertanyaan
pertama setelah restart lebih lambat beberapa detik.

### 5. Kalibrasi ulang ambang penolakan (FR-3)

Ini langkah yang paling sering terlewat.

`VECTOR_THRESHOLD` (default `0.35`) dikalibrasi untuk sebaran skor model
OpenAI. Skor cosine e5 menumpuk jauh lebih tinggi, umumnya 0,7–0,9, bahkan
untuk pasangan pertanyaan–dokumen yang tidak berhubungan. Dengan ambang lama,
hampir semua pertanyaan lolos ke LLM, dan penolakan FR-3 praktis tidak pernah
terjadi.

```bash
python -m eval.calibrate_threshold \
  --dataset eval/data/eval_set.jsonl \
  --negatives eval/data/negatives.txt
```

Terapkan hasilnya lewat halaman **Konfigurasi** di dashboard (berlaku seketika,
tanpa restart), atau lewat `VECTOR_THRESHOLD` di `.env`. Lihat juga bagian
"Kalibrasi ambang (FR-3)" di `README.md`.

Bila reranker menyala dan `RERANK_THRESHOLD` terisi, keputusan FR-3 memakai
skor reranker, yang tidak bergantung pada model embedding. Ambang reranker
tidak perlu diubah, tetapi `VECTOR_THRESHOLD` tetap perlu disesuaikan untuk
jalur tanpa reranker.

### 6. Evaluasi

```bash
python -m eval.run_eval --dataset eval/data/eval_set.jsonl --k 5
```

Target Recall@5 ≥ 0.85; exit code 1 bila belum tercapai. Simpan juga hasil
dengan model lama sebelum berpindah, supaya ada pembandingnya.

Setelah layanan berjalan, pantau halaman **Log** di dashboard:

- **Durasi per langkah → Pencarian dokumen.** Embedding kini memakai CPU
  server; p95 langkah ini naik dibanding model API.
- **Tempat alur berhenti.** Porsi "Penolakan" yang jatuh mendekati nol adalah
  tanda ambang langkah 5 belum disesuaikan.

## Apa yang ditangani otomatis

- **Awalan e5.** Model e5 dilatih dengan `query: ` di depan pertanyaan dan
  `passage: ` di depan dokumen; tanpa awalan itu kualitas retrieval turun
  tanpa pesan galat. Awalan dipasang otomatis untuk setiap model yang namanya
  mengandung `e5`.
- **Dimensi.** Vektor dinormalisasi lalu diisi nol sampai 1024. Hasil kali
  titik dan norma tidak berubah oleh nol tambahan, jadi cosine similarity
  identik dengan vektor aslinya. Skema database dan index HNSW tidak perlu
  dimigrasi.
- **Biaya.** Embedding lokal ditandai berbiaya nol, bukan "tarif tidak
  diketahui". Di halaman Biaya, embedding pertanyaan tercatat $0.
- **Dokumen baru.** Unggahan setelah perpindahan langsung di-embed dengan e5;
  jalur ingestion memakai `EMBED_PROVIDER`/`EMBED_MODEL` yang sama.

## Docker

- `Dockerfile` memasang `uv pip install --system .` tanpa ekstra. Ganti menjadi
  `".[local]"` supaya sentence-transformers ikut terpasang.
- Mount cache Hugging Face sebagai volume (mis. `-v hf-cache:/root/.cache/huggingface`),
  atau model diunduh ulang setiap container dibuat ulang.
- Perhitungkan memori: torch + e5-small butuh kira-kira 1 GB RAM di proses API.

## Kembali ke model API

```env
EMBED_PROVIDER=api
EMBED_MODEL=openrouter/openai/text-embedding-3-small
```

Lalu ulangi langkah 3–5: re-index, restart, dan kembalikan ambang ke nilai
hasil kalibrasi untuk model API. Ekstra `local` boleh tetap terpasang.

## Pemecahan masalah

| Gejala | Penyebab | Tindakan |
|---|---|---|
| `ModuleNotFoundError: sentence_transformers` | ekstra `local` belum terpasang | `uv sync --extra local` |
| `model menghasilkan N dimensi, melebihi kolom chunks.embedding (1024)` | model di luar keluarga e5 dengan dimensi > 1024 | pilih model ≤ 1024 dimensi |
| Jawaban tidak nyambung dengan pertanyaan | re-index belum dijalankan, atau API belum di-restart | langkah 3 lalu 4 |
| Chatbot hampir tidak pernah menolak | ambang belum dikalibrasi untuk e5 | langkah 5 |
| Pertanyaan pertama setelah restart lambat | model dimuat saat pertama dipakai | normal; hanya sekali per proses |
| Gagal mengunduh model | server tanpa akses ke huggingface.co | unduh di mesin lain, salin cache-nya, isi `HF_HOME` |
